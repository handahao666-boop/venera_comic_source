# 栗子漫画 1.2.4：API 域名恢复

日期：2026-11-04。原源作者：[Walter498](https://github.com/Walter498)，来源仓库：[Walter498/Walter](https://github.com/Walter498/Walter)。本次基于本仓库 1.2.3 修复，保留 key `lizimh` 和本仓库更新直链。

## 原因与修改

用户日志中，旧 API `ai.xajtl.com` 和 `ai.qsmm.fun` 的配置与首页请求均出现 DNS 11001，未到达漫画业务接口。当天 Google 公共 DNS 查询也返回 NXDOMAIN（Status=3）；本机代理的合成 IP 不代表源站仍然有效。原作者当天公开脚本仍使用这两个地址。

原应用的域名发现逻辑使用公开 TXT 配置 `adnet.lizimh.com` / `adnet.lizi.lat`。本次从前者读取并解码得到 `https://mh.lizimh.net/`；公开配置、首页、作品详情均 HTTP 200、业务 code=201。

- 默认入口更新为服务方配置下发的 HTTPS 域名，不再请求上述旧域名。
- 公开接口网络失败后，读取上述官方 TXT 配置，通过 Google / AliDNS 的 HTTPS 查询获取；解码后仅接受不带路径、端口、账号信息的 HTTPS 主机名，不接受 IP 字面量。
- 使用不带个人凭据的公开配置接口核对候选入口，成功后更新当前运行实例的入口，并重新请求一次原公开接口。缓存会话、漫画内容和阅读权限不由此生成。
- 域名发现合并并发请求；失败后30秒内不重复发现；重复入口去重。公开 API 等待上限8秒、配置查询5秒，超时只结束等待，不能取消 Venera 的底层连接。
- HTTP 401/403/429 或业务拒绝直接报告，不以轮换域名重复请求。
- 脚本、内部诊断信息与本地索引版本同步至1.2.4。

## 回归结果

1. 实际 Venera SDK + QuickJS 模拟：6组通过。包括初始化、首页和842条目录、图片 ArrayBuffer 回调、DNS失败后的TXT恢复、并发合并、权限拒绝不重放、非法配置拒绝及失败退避。测试使用模拟响应与人工控制计时器，不是手机实机测试。
2. 真网：加载完整交付脚本和实际 SDK，仅发送匿名公开 GET，共50次请求。首页3个分区36部作品；《一人之下》目录842条，第1章取得20张清单，抽查第1/11/20张；《我！天命大反派》第3话取得128张清单，抽查第1/65/128张。
3. 上述6张正文及2张封面共8张图片全部下载并经 Pillow 完整解码。另一个最新章章节缩略图返回404，未把它计为通过；未处理原站这张图片缺失。
4. 新版文件名章节仍需要原站返回真实图片清单；本轮没有登录、请求广告奖励或重新验证需账号权限的正文，没有手机原生界面验收。域名修复不代表所有最新章节可以匿名阅读。
